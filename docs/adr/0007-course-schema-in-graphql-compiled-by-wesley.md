# 7. Define the course schema with GraphQL SDL, compiled by Wesley

Date: 2026-11-21 · Status: Accepted

> **Amended 2026-11-21.** "Lesson file" is now **course file** ([glossary](../glossary.md)), and this decision is **no longer settled**. [ADR 8](0008-the-school-skill-and-who-invokes-whom.md) establishes that the server plays prepared lessons and only calls an agent for subjective grading and preparation, which shrinks what a course file must carry to the machine-readable parts the server needs. Whether that still warrants a GraphQL schema compiled by Wesley, rather than plain JSON Schema or no schema language at all, is open. Wesley also emits no JSON instance validator: its TypeScript output is types, which erase at runtime.

## Context
[ADR 6](0006-separate-framework-lessons-and-learner-state.md) made the compiled course file the only interface between a lesson course and the framework, and noted that such an interface needs a declared layout and a format version. It has neither today.

The block model is hand-written TypeScript in `server/blocks.ts`: the types `page`, `section`, `prose`, `card`, `quote`, `aside`, `quiz`, `explain` and `nest`, with `{ "ref": id }` reuse and validation written by hand — which is why reference cycles still go undetected. Nothing outside this repository can read that format, there is no version attached to it, and the only possible implementation is this server.

A course author needs to know what a valid course file is. School needs to reject one it cannot read, and say why. Neither is possible without a schema that exists apart from the code that happens to parse it.

## Decision
The course file format is defined as **GraphQL SDL**, held in this repository, and compiled by **[Wesley](https://github.com/flyingrobots/wesley)** — a compiler that lowers GraphQL SDL to a deterministic IR, hashes it, diffs it for breaking changes, and emits Rust and TypeScript.

- **The schema hash is the format version.** `wesley schema hash` computes it from the lowered IR rather than the file's bytes, so comments and whitespace do not change it while type and field order do. Every compiled course file records that hash and the Wesley version that produced it, the way Echo binds the pinned `wesley-core` version into each generated artifact's provenance.
- **The server reads generated types.** `wesley emit typescript` produces the TypeScript that replaces the hand-written block interfaces in `server/blocks.ts`. `server/render.ts`'s exhaustive `switch` keeps working, because Wesley emits a GraphQL union as a TypeScript union type alias.
- **Breaking format changes are gated.** `wesley schema diff --breaking-only --exit-code` fails CI on a change that would make existing courses unreadable, so a new format version is a deliberate act. `wesley schema diff --schema <path> --against <rev>` diffs against a git revision, which suits a format whose history lives in git.
- **The block tree is a union.** Heterogeneous children are a GraphQL `union`, recursion goes through object fields. Verified against this checkout: `wesley-core` lowers union and interface definitions, its `schema_delta` tracks union-member and implemented-interface changes, and `wesley-emit-typescript` maps a union to a TypeScript type alias.
- **Wesley is pinned exactly** at `0.3.0-alpha.4`. It is pre-1.0 and says so: the CLI, the library APIs and the emitted code may change between releases.

GraphQL is used here as a schema language for a document format. There is no query API, no resolvers and no execution.

## Alternatives
- **Keep hand-written TypeScript types as the specification.** The status quo. The format is then only legible to someone reading the server, it carries no version, and no second implementation can exist.
- **TypeScript types plus a runtime validator such as zod.** No new toolchain and validation in the implementation language, but still no format version, no breaking-change gate, and a format that stays TypeScript-shaped rather than language-neutral.
- **JSON Schema.** Broad tool support and no Rust dependency. Rejected because versioning and breaking-change detection would be hand-rolled, and it offers no multi-language code generation from the same source.
- **Protobuf or Cap'n Proto.** Real schema evolution and codegen, but a heavier IDL for what is a document, and further from the stack this author already maintains.

## Consequences
- **[ADR 2](0002-typescript-on-bun.md) is amended.** It chose one TypeScript file on Bun, built-ins only, no `package.json` and no build step. School now has a build step and a tool outside the Bun world (Rust, via `cargo install wesley-cli`). The runtime is unchanged: generated TypeScript is just source, and Bun still runs the server with built-ins. The course compiler is a separate program from the server.
- **Generated output is committed**, marked `// @generated by Wesley. Do not edit.` Otherwise the server could not run from a clean checkout without a Rust toolchain. A learner who only studies never needs Wesley; only a course author or a framework developer does.
- A Wesley upgrade becomes a reviewable diff of generated code, which is the point of committing it. Pinning is not optional while Wesley is pre-1.0.
- **SDL constrains shape, not every rule.** Unique block IDs, a `ref` that resolves, and the absence of reference cycles are not expressible as types. They stay compiler checks, which ADR 6 already moved to compile time. Wesley's `law` documents may be able to carry some of them; that is unexamined.
- The format hash joins the [learning record contract](../rfc/0001-school.md#the-learning-record-contract): private state records the format version it was written against, alongside the content hash of the course it refers to.
- Wesley's model includes root operations, which a document format may not need. To be settled when the schema is actually written.

## Open
- Whether the compiled artifact is JSON or Wesley's little-endian binary (`wesley emit le-binary-typescript`). Binary is compact and comes with a codec; JSON stays readable and diffable inside a course repository.
- Whether `wesley law` covers the structural rules above, or they remain hand-written in the compiler.
- Whether the schema lives here, because the framework owns the format, or in its own repository. Leaning towards here.
